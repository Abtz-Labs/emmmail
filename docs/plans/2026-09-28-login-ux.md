# Login page UX: remembered email, submit spinner, smart autofocus

**Status:** done
**Date:** 2026-09-28

## Problem

The login page makes the user retype and refocus:

1. The last used email is not remembered across visits.
2. Submitting gives no feedback that the login is in flight.
3. `autofocus` always lands on the email field, even when the email is already
   prefilled (returning user), so the cursor is in the wrong place.
4. The inputs carry no `autocomplete` hints, so password managers are left to
   guess.
5. A double Enter/click can fire two logins.

## Goal

- Remember the last used email in `localStorage` and prefill it on the next
  visit.
- Show a spinner on the Sign in button while the POST is in flight, and block a
  second submit.
- Focus the email only when it is empty; focus the password otherwise.
- Add `autocomplete="email"` / `autocomplete="current-password"`.

---

## Plan

### Step 1: Server-side `view_login()` (index.php ~line 7741)

- Password input gets `id="login-password"` so JS can target it.
- `autofocus` moves: email gets it when `$email === ''`, password gets it when
  `$email !== ''` (mirrors `view_compose()`, which focuses To when blank and
  Body when prefilled).
- Email input: `autocomplete="email"`. Password input:
  `autocomplete="current-password"`.
- Sign in button gains an icon (`arrow-right`) so `markBusy()` has a `<use>` to
  swap into a spinner.

### Step 2: JS login block (js_inline(), after the preset toggle ~line 6500)

Guarded by `$('#login-email').length` so it only runs on the login page:

- Read `localStorage['emmmail-last-email']`; if the email field is empty, fill
  it.
- Focus: if email has a value → password, else → email (this overrides the
  server `autofocus` for the localStorage case).
- On form `submit`: save the email to `localStorage`, then `markBusy()` the
  submit button and guard a second submit (`if busy → return`).

### Step 3: Tests

- **unit.php** (near the existing `view_login` group at ~line 1485):
  - empty email → email carries `autofocus`, password does not
  - prefilled email → password carries `autofocus`, email does not
  - password has `id="login-password"`
  - email has `autocomplete="email"`, password has `autocomplete="current-password"`
  - button carries an icon (`<use href="#tabler-arrow-right"`)
  - `js_inline()` ships the localStorage key and the login submit guard
- **js.php** (new S33, after S32):
  - builds a login form (email, password, submit button)
  - no stored email → email focused
  - stored email → field prefilled and password focused
  - submit → email persisted to localStorage
  - submit → button marked busy (icon swapped to `#tabler-progress`); a second
    submit event does not re-mark/post

  JS-off, JS moves the focus after the localStorage prefill.
